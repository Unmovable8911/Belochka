Belochka (белочка) — инструмент мониторинга серверов в виде единого бинарного файла, предназначенный для небольших групп серверов Linux. Поддерживает постоянные SSH-соединения с 5–20 удалёнными машинами и передаёт метрики CPU, памяти, дисков, сети и процессов в реальном времени на панель управления в браузере через WebSocket. Также предоставляет веб-терминал для прямого SSH-доступа — отдельный SSH-клиент не требуется.

## Возможности

- **Группы серверов** — организация серверов в плоские группы верхнего уровня в боковой панели; создание, переименование и удаление групп, перемещение серверов в группу или из неё перетаскиванием или через меню «Переместить в…»; клик по группе фильтрует панель по её серверам, с навигацией по хлебным крошкам
- **Панель мониторинга в реальном времени** — карточки серверов с актуальными метриками CPU, памяти, дисков и сети, окрашенные по уровню нагрузки; правый клик по карточке открывает быстрые действия Изменить / Удалить / Консоль
- **Детальный просмотр сервера** — индикаторы CPU по каждому ядру, кольцевые диаграммы памяти/swap, детализация по разделам дисков, пропускная способность сетевых интерфейсов
- **Управление процессами** — вкладка Процессы с плоской сортируемой таблицей (регулируемая ширина столбцов), поиском по нескольким ключевым словам, автообновлением и завершением с выбором сигнала SIGTERM/SIGKILL (sshd/init/systemd защищены)
- **Веб-терминал** — полноценная интерактивная SSH-консоль в браузере через xterm.js
- **Иконка в системном трее** — на десктопных машинах (Windows, macOS, Linux с GNOME/KDE/XFCE) отображает иконку в трее с пунктами **Открыть панель** и **Выход**; автоматически переключается в режим CLI на серверах без графической среды
- **Аутентификация** — защита паролем и сессионными cookie; при первом посещении предлагается двухшаговый мастер настройки (выбор языка → установка пароля с индикатором надёжности и подтверждением); ограничение после 10 неудачных попыток входа (блокировка на 30 минут)
- **Единый бинарный файл** — Go-бэкенд со встроенным React-фронтендом; для развёртывания достаточно одного файла
- **Постоянные SSH-соединения** — автоматическое переподключение с экспоненциальной задержкой и keepalive; перед сохранением сервера можно проверить соединение, а при добавлении машины отображается отпечаток ключа хоста для проверки по принципу доверия при первом подключении
- **Загрузка ключей через браузер** — загрузка файлов приватных SSH-ключей прямо через интерфейс; ключи проверяются, сохраняются с UUID-именами, потерянные файлы автоматически очищаются
- **Шифрование учётных данных** — пароли серверов зашифрованы при хранении с помощью AES-256-GCM
- **Управление cron-задачами** — просмотр, добавление, редактирование, включение/отключение, удаление и немедленный запуск cron-задач прямо на странице сервера
- **Пакетная команда** — напишите многострочный скрипт и отправьте его на любой набор серверов из боковой панели; терминальный вывод каждого сервера транслируется в диалог в реальном времени, можно отвечать на запросы и отменить выполнение в любой момент
- **Постоянный лог-файл** — весь вывод записывается в `belochka.log` рядом с бинарным файлом (или в текущий рабочий каталог при запуске через `go run`) с автоматической очисткой по сроку хранения (по умолчанию: 3 дня)
- **Многоязычный интерфейс** — английский, упрощённый китайский, французский, русский, немецкий, испанский, португальский, традиционный китайский и итальянский; выбирается при начальной настройке и может быть изменён в диалоге настроек; язык браузера предварительно выбран
- **Встроенные настройки** — настраивайте порт, каталог данных, язык и срок хранения логов прямо из интерфейса через иконку шестерёнки в заголовке панели управления

## Быстрый старт

Скачайте последний бинарный файл со страницы [Releases](https://github.com/Unmovable8911/Belochka/releases) и запустите:

```bash
# Linux (amd64)
chmod +x belochka-linux-amd64
./belochka-linux-amd64

# Windows (64-бит)
belochka-windows-x86-64.exe
```

Откройте `http://localhost:53136` в браузере. При первом посещении вам будет предложено выбрать язык и установить пароль — он защищает панель управления и все API-эндпоинты. После настройки вы автоматически войдёте в систему. Добавляйте серверы через интерфейс.

## Сборка из исходников

Требуется Go 1.25+ и Node.js 18+.

```bash
git clone https://github.com/Unmovable8911/Belochka.git
cd Belochka
make build
./bin/belochka
```

Кросс-компиляция релизных бинарных файлов для всех платформ:

```bash
make release
# Результат:
#   bin/belochka-linux-amd64
#   bin/belochka-linux-arm64
#   bin/belochka-windows-x86-64.exe
#   bin/belochka-windows-x86.exe
```

## Конфигурация

Belochka работает «из коробки» без конфигурации. Все настройки доступны через **диалог настроек** (иконка шестерёнки в заголовке панели управления). При первом запуске файл `config.json` со значениями по умолчанию автоматически создаётся рядом с бинарным файлом. Также можно передать `--config путь/к/config.json` для указания другого расположения:

```json
{
  "port": 53136,
  "data_dir": "./data",
  "language": "",
  "log_path": "",
  "log_retention_days": 3
}
```

| Поле | По умолчанию | Описание |
|---|---|---|
| `port` | `53136` | Порт HTTP-сервера |
| `data_dir` | `./data` | Расположение базы данных, ключа шифрования и загруженных SSH-ключей (`data/keys/`) |
| `language` | `""` | Язык интерфейса (`en`, `zh`, `fr`, `ru`, `de`, `es`, `pt`, `zh-TW`, `it`); определяется автоматически при первом посещении, если не задан |
| `log_path` | `""` | Путь к лог-файлу; по умолчанию `belochka.log` рядом с бинарным файлом |
| `log_retention_days` | `3` | Количество дней хранения записей в лог-файле |

Изменения `port` и `data_dir` требуют перезапуска; `language` и `log_retention_days` применяются немедленно через диалог настроек.

### Флаги

| Флаг | Описание |
|---|---|
| `--config <путь>` | Путь к файлу конфигурации JSON |
| `--no-tray` | Отключить иконку в трее; запустить как CLI-процесс |
| `--version` | Вывести версию и выйти |

### Переменные окружения

| Переменная | Описание |
|---|---|
| `BELOCHKA_ENCRYPTION_KEY` | Ключ AES-256 для шифрования паролей; при первом запуске генерируется автоматически, если не задан |

### Ключ шифрования

При первом запуске без заданного ключа Belochka автоматически генерирует его в `{data_dir}/encryption.key` и выводит предупреждение в логах. Для production-окружения рекомендуется явно задать ключ через переменную окружения.
